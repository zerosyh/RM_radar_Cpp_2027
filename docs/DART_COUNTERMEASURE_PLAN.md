# 反导（反飞镖）实现方案分析

> 编写日期：2026-08-23
> 编写依据：RM2026 比赛规则手册 V2.1.0（5.6.5 飞镖系统特殊机制 / 4.2.2 基地 / 4.2.3 飞镖发射站 / 4.2.5 雷达基座）、现有雷达架构（lidar.cpp / radar.cpp / HNURM 2026 Python 版 lidar_node.py / T-DT RadarWarn）
> 一句话目标：**对方飞镖自发射站起飞后，我方 Livox HAP 点云在 ≤0.5s 内捕获其弹道，在 ≤1s 内输出可用于反制的预测落点/拦截点，并随每帧更新直到命中或失效。**

---

## 0. 结论摘要（TL;DR）

1. **现有代码没有反导能力**。`lidar.cpp::isDartRegion`（lidar.cpp:118-122）只是一个 0.19m×0.6m×0.86m 的静态盒子（蓝方基地飞镖检测模块/引导灯附近），当盒内点云 >5 点时打一条 `RCLCPP_WARN("发现飞镖！")` 日志。它只能感知"有东西碰到了目标区域"，**没有轨迹、没有预测、没有对外发布、没有反制点**，而且触发时机接近命中时刻——对反导毫无价值。
2. **反导的本质是弹道预测**：检测（每帧）→ 多目标关联（KF）→ 抛物线拟合（≥3 帧，即 ~0.3s）→ 弹道外推 → **反制点 = 飞镖弹道与"命中面/哨兵弹道"的交点**。飞镖飞行时间假设 3~6s，检测+拟合耗时 ~0.5s，剩余 ≥2.5s 的窗口完全够用，时效性不是瓶颈；**瓶颈是可见性与检测可靠性**（FOV 覆盖、遮挡、与空中机器人/无人机区分）。
3. **输出建议分两级**：
   - **主输出 /dart_target**：预测命中点 `(x, y, t_hit)`（场地坐标系 28×15，含 z 与不确定度），供操作手 UI 预警 + 哨兵决策；
   - **扩展输出 /dart_intercept**：哨兵弹丸弹道与飞镖弹道的**交会点（拦截点）** `(x, y, z, t_intercept)`，供哨兵云台直接瞄准开火（若规则允许/团队确认）。
4. **立即可以开始的非阻塞项**：飞镖走廊区（对方半场 z>1.4 空域）的背景减除改造 + 离线弹道拟合仿真（用仿真/实测数据验证抛物线模型精度）。这两步不依赖任何规则澄清。

| 飞镖目标 | 对方前哨站 / 基地的飞镖检测模块 | 命中面 = 对方（我方防守时即**己方**）前哨站/基地顶部模块 |

| 需求 | 现状 | 差距 |

## 3. 总体架构与数据流

```
Livox HAP ──/livox/lidar──→ [lidar]
                               │ ① 走廊区背景减除（新增）
                               │ ② 飞镖/无人机判别（运动学）
                               ▼
                    target_pointcloud / livox/lidar_other（沿用）
                               │
                               ▼
                        [dart_tracker]（新增节点，或并入 radar 节点）
                          - 多目标轨道池（恒加速 KF, 每目标编号 D1..Dn）
                          - ≥3 帧启动弹道拟合（LSQ+RANSAC，抛物线）
                          - 每帧外推 → 命中面（z=模块装甲面）求交
                               │
                               ├─ /dart_target      (PointStamped + t_hit + 不确定性 + 目标类型)
                               ├─ /dart_feature     (调试：拟合残差/轨道点数/速度)
                               ▼
                   [display_panel] 预警图标/落点显示   [sentry_decision] 哨兵增援/拦截决策
                               ▼
                   [judge_messager]（可选：作为裁判系统坐标上报的附带信息，不阻塞）
```

关键点：
- **反制点必须在场地（map）坐标系输出**（radar 的 r2f_ 变换已具备），哨兵/操作手直接用；
- **每帧更新**：飞镖检测到 → t+0.1s 首版弹道 → t+0.3~0.5s 收敛版 → 后续帧持续更新直到命中或飞出 FOV；
- 与现有 `location`（车辆）、`sentry_targets`（哨兵）并行，不互相干扰。

## 4. 模块设计

### 4.1 飞镖走廊与背景减除（改造 lidar.cpp）

飞镖从对方发射站（对方场边、基地区内）起飞，沿抛物线飞向**己方**前哨站/基地的模块。飞镖空域：**对方半场 x∈[2,14.5]（红方飞镖）或 x∈[13.5,27]（蓝方飞镖），z∈[1.4,3.5]（高于地面车辆、低于雷达视线上限）**。当前 main_cond 把 z>1.4 全部排除到 `other`，且 `other` 不做背景减除——意味着移动的飞镖点云与静态建筑物（飞镖站主体、高灯架、框架）混在一起，无法直接聚类。

**改造方案**：
1. 为走廊区建立 **kd-tree 背景减除**（复用 extractDynamic 的 nearestKSearch 阈值 0.20m 逻辑，用离线 `map.pcd` 作为背景参考点，**key：只把走廊区内的背景点建树，避免全场 700 万点查询开销**）；
2. 走廊区静态盒（飞镖发射站滑台、引导灯架）作为**已知静态掩膜**直接剔除（这些结构不动）；
3. 输出 `dart_dynamic`（新点云 topic 或并入 `livox/lidar_other`），供 dart_tracker 消费。

> 注意：滑台滑出/闸门开启是**动态**的（守方策略：发射前预警，见 4.5），它不能被背景减除吞掉——需要保留 `isDartRegion` 盒作为**滑台事件检测器**（阈值调优：>5 点即滑台有物，时序上比飞镖升空早 ~1-2s）。

### 4.2 快速检测（运动学判别）

飞镖在 10Hz 下每帧位移 1.5~2.5m（按 15~25 m/s 估算），这是最强的判别特征：

- **帧间匹配**：对走廊动态点做轻量 DBSCAN（eps≈0.2m, min≥5 点——飞镖 1m 长细圆柱近距时 20~100 点），聚类中心按最近邻匹配到上帧中心；
- **速度门槛**：跨帧速度 > 8 m/s 且 < 35 m/s → 飞镖候选（无人机悬停/缓移 < 3 m/s，直接排除）；
- **形态过滤**（可选增强）：飞镖细长（长径比 >4：Z 方向拉伸比横向大），主成分分析第一特征值 >> 第二/三；
- **高度过滤**：轨迹点 z 单调先升后降（抛物线）且峰值 z∈[1.4,3.5]。

### 4.3 多目标轨道池（恒加速 KF)

沿用 radar.cpp 的 KF 模式（sigma_q/sigma_r 调整；飞镖建议 Q 更大、R≈0.05）：

- 状态 `[x,y,z,vx,vy,vz,ax,ay,az]`（恒加速恒重力模型，可直接退化为抛物线）；
- 匹配门限：`max_speed×dt + 0.3m`（连续两帧同轨）；
- 删除策略：**连续 5 帧未更新（0.5s）删除**（飞镖快速移动，3s 不更新多半已丢失/命中，不再保留 last_known——与车辆不同）；
- 编号 D1..Dn，支持 4 枚同空（30s 窗口内连续发射）。

### 4.4 弹道拟合与命中点预测（核心）

**飞镖建模为自由抛物线**（或带弱阻力修正）：

```
P(t) = P0 + V0·t + ½·g·t²      (g = [0,0,-9.80665] 修正后)
```

拟合策略（每帧输出一次）：
1. **LSQ 二次多项式**，分别对 x(t)、y(t)、z(t) 独立拟合（t 取相对首帧时间）；
2. **RANSAC**（iter=30, 内点阈值 0.15m）剔除点云中心抖动产生的离群帧（飞镖点云中心每帧 ±5cm 抖动是常态）；
3. **置信度**：基于内点数量、残差 RMS、轨道年龄（帧数）。帧数 <3 → 只发检测状态，不发反制点；
4. **动态权重**：距离越远、z 越高的帧权重降低（HAP 远处点稀疏）。

**命中面求交**：命中面 = 己方飞镖检测模块（小装甲模块）所在平面。模块数据来源：
- 模块静态初始位置 + 移动范围（±280mm 沿 y），可由**比赛自检阶段**（三分钟准备 + 15s 自检期间引导灯全亮）用点云/相机精标模块位置 → 得到 `DART_MODULE_HOME`（x,y,z 基准）与装甲面法向（朝上/朝侧）;
- 命中判定面取 `z = z_module_top`（近似水平面），解 `z(t)=z_module_top` 的 t（二次求根，取飞行后段的大根）→ 反代入 x(t),y(t) 得落点；
- **不确定度输出**：落点 y 给出 `±0.28m`（模块移动带）∩ 拟合 95% 置信带；x 同置信带。**反制点消息必须携带 σ 字段，哨兵/操作手据此判断硬拦截可行性与瞄准点在带内取法**。

### 4.5 两级预警（建议先做，收益/成本比最高）

| 级别 | 时机 | 依据 | 动作 |
|---|---|---|---|
| L0 发射前 | 闸门开启后 ~1-2s（滑台滑出） | isDartRegion 盒点云出现 | 预警"飞镖进入准备"；若雷达为旋转扫描，**将扫描步进指向该区域**（主动引导） |
| L1 飞行中 | 飞镖升空 +0.3s | 走廊区检测+弹道拟合 | 每帧输出 /dart_target（命中点+时刻） |

L0 能比 L1 提前 1~3s 给出"飞镖即将来袭"，对操作手人类决策（撤离/增益时机/金币分配）极有价值，且实现=现有代码 + 一条正式消息，**无需弹道拟合**。**强烈建议 L0 与 L1 同时做。**

### 4.6 哨兵拦截交会点（扩展，需团队决策）

若决定哨兵用弹丸物理拦截飞镖：
1. 获取哨兵弹丸模型：初速 v_b（17mm 常用 25~30 m/s，以实测为准）、重力/阻力（弹丸在小距离内近似直线）；
2. 解算交会：求 `t*` 使 `P_dart(t*) = P_sentry + v_b·(t*-t_fire)`（迭代或数值求根，飞镖弹道已参数化，2~3 次迭代收敛）；
3. 输出拦截点 `(x,y,z,t*)` + 期望开火时刻 t_fire（含哨兵云台指向时间延迟）；
4. **命中概率判据**：拦截点处飞镖-弹丸相对速度 ~40-50 m/s、目标直径 ~0.1m → 需瞄准误差 <0.05m，硬拦截命中率估计 10~30%（乐观）。**因此强烈建议输出策略为"打偏飞镖"：瞄准飞镖红外触发装置（飞镖前端）或预测落点附近提前量，而非瞄准质心。**
5. 若本队哨兵任务优先级更高（防空/守家），可只发预警，不拦。

## 5. 时序预算（"极短时间"论证）

| 阶段 | 耗时 | 累计 |
|---|---|---|
| 点云采集（HAP 10Hz） | 0~0.1s | 0 |
| 走廊背景减除 + 聚类 + 匹配 | <20ms | ~0.1s |
| 帧 1 探测到飞镖（首次发现） | — | 0.1s |
| 帧 2 速度确认（>8m/s） | 0.1s | 0.2s |
| 帧 3 轨道初始化（KF 起） | 0.1s | 0.3s |
| 帧 4 首版弹道 LSQ（3 点，RANSAC 启动） | 0.1s | **0.4s** |
| 帧 5-6 收敛版弹道（5 点，残差稳定） | 0.1~0.2s | **0.5~0.6s** |
| 命中面求交 → /dart_target 发布 | <5ms | **≤0.6s** |

飞镖飞行按 3~6s 计：**T+0.6s 出首个反制点，剩余 2.4~5.4s** 供操作手/哨兵使用；之后每 100ms 刷新。命中预测精度随时间提升：帧 6 时落点误差经验值约 ±0.1~0.3m（取决于探测距离与点数）；**到最后 1s 内预测落点 σ<0.1m，足以覆盖 0.28m 模块移动带内多数情况。**

## 7. 关键技术风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| FOV 覆盖 | 70°×70° 若固定朝向，飞镖起飞段可能在视野外 | 雷达旋转扫描 + 滑台预警（L0）引导；或飞镖走廊在 FOV 内时仅需确认；**实测场地视野** |
| 遮挡 | 对方飞镖站可能被对方基地/城堡/飞镖站主体遮挡 | 用场地 PCD 做射线遮挡分析；尽量选取雷达高度与位置使得走廊净空 |
| 与无人机混淆 | 无人机也可能在空域（但停机坪区 z 1.7-3.5） | 运动学区分（悬停 vs >8m/s）；轨道特征（抛物）；y/z 走廊约束 |
| 模块随机移动 | 命中面不确定 | 落点带 ±0.28m；反制点对**模块移动预测**（移动在发射后 0~600ms 完成，之后静止——末端/随机移动目标在 t 已静止） |
| 多目标 | 30s 内 4 连发 | 轨道池编号，一对一匹配 |
| 点云稀疏/抖动 | 远距、高角度处点少，聚类中心抖动 | RANSAC 拟合；保留原始点云中心而非降采样中心 |
| 背景减除假阳性 | 走廊区建筑物/灯光架 | 静态掩膜剔除 + 运动学门槛（速度>8m/s 已滤除绝大多数） |
| 雷达自旋转运动补偿 | 旋转扫描时点云需按时间戳运动补偿 | 若旋转：按 each-point timestamp 补偿（HAP 带时间戳），单帧内旋转量可能 >0.5m |

---

## 8. 验证方案（先离线，后实机）

1. **数据采集**：真实飞镖飞行 bag（含发射全流程：闸门开→滑台出→升空→飞行→命中），≥3 次，同一场地；
2. **离线验证管线**（Python，参照 lidar_test_gff.py 做法）：
   - 回放 bag → 重放走廊背景减除 + 检测 + 跟踪 + 拟合；
   - 与**真值**（人工标注飞镖中心轨迹 + 命中前后引导灯亮为止）对比：检测召回率、拟合落点误差、首次检测延时；
   - 指标：`首检延时 <0.5s`、`落点误差 <0.3m（命中前 1s）`、`全流程误报 <1 次/10min`；
3. **仿真兜底**（无实机数据时）：用 Isaac Sim / 规则数字人按 15~25 m/s、发射角 40°~50° 生成合成点云，用与 1 相同的管线验证数学正确性（目标：数学不出错，参数靠实测）；
4. **实机联调**：与哨兵实弹测试（哨兵瞄准 /dart_intercept 的开火结果）；记录命中率，验证拦截价值。

## 9. 分阶段实施计划

| 阶段 | 内容 | 交付物 | 依赖 |
|---|---|---|---|
| P0（1 天） | 走廊背景减除改造 + isDartRegion 参数配置化 | lidar.cpp 改造 + 配置项；离线可视化工具 | 无 |
| P1（3 天） | dart_tracker 离线仿真（合成抛物数据） | 拟合精度报告；落点误差 <0.3m 证明 | P0 |
| P2（3 天） | ROS2 节点集成 + /dart_target 发布 + display 显示 | 实机 bag 回放输出反制点 | P1 |
| P3（3 天） | 哨兵拦截交会解算 + 实弹测试 + 调优 | 拦截命中率数据；参数表定稿 | P2 + 团队决策（是否拦截） |
